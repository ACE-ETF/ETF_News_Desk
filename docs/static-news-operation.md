# 무료 독립 운영 (기존 주소 유지)

운영 주소: https://ace-etf.github.io/ETF_News_Desk/

- 기존 Pages 주소와 화면을 사용합니다.
- 수집 메타데이터·번역·공개 JSON은 news-data 브랜치에 보존합니다.
- GitHub가 제공하는 GITHUB_TOKEN만 사용합니다. 별도 사용자 키·유료 AI API는 필요하지 않습니다.
- 매일 01:10·07:10·13:10·19:10 KST에 누적하고 영업일 07:40 이후 공개합니다.
- 06:45 KST 조기 실행은 07:40까지 대기한 뒤 공개하며, 07:40 정규 공개와 07:47·08:17 저장본 복구 예약을 유지합니다. 모두 GitHub 예약으로 실행 시각이 지연되거나 일부 실행이 누락될 수 있습니다.
- 별도 클라우드 예약 `Automation_723c67a47ff481919cd97e91c1136240`는 한국 평일 07:40·08:40에 실제 공개 상태를 확인합니다. 미갱신일 때만 Contents API로 `ops/publication-retry.json`을 갱신해 push 실행을 시작합니다. 예전 07:55·08:55 예약은 이 시각으로 변경했습니다.
- 복구는 저장 기사가 있으면 `stored-release`를 우선합니다. 같은 구간 요청은 최대 2회, 15분 이내 중복 요청은 생략합니다. 요청 접수 이후 build·deploy와 실제 공개 JSON을 확인해야 완료로 판단합니다.
- 수집·공개 실행은 직렬 처리하고 복수 대기를 허용해 새 이벤트가 대기 중인 공개를 취소하지 않게 합니다. 배포 확인은 실제 구간·갱신 시각·건수가 해당 빌드의 공개본과 같은지 검사합니다.
- GitHub 예약은 지연될 수 있습니다. 공개본이 갱신되지 않으면 노란 안내가 자동 표시됩니다.
- 주말·한국 휴일은 다음 영업일에 합산합니다. 0건은 이전 공개본을 유지합니다.
- 직접 RSS 3개·Google 보조 검색 2개를 최대 5초 이상 간격으로 한 번씩 요청합니다.
- 회차 선점은 요청 전에 별도 커밋으로 저장하며, 같은 회차는 RSS를 다시 요청하지 않습니다.
- 해외 제목은 무료 Argos en→ko 모델을 CTranslate2 CPU로 실행합니다. 손상된 숫자·티커 번역은 저장하지 않습니다.
- 확인 가능한 국내 본문의 짧은 발췌만 저장하며 전문·미검증 이미지는 저장하지 않습니다.
- 기존 서버의 R2 데이터는 삭제하지 않습니다. 이전 기록의 자동 이전은 아직 수행하지 않았습니다.
- 수집·번역 실패의 세부사항은 rss.html 및 실행 로그에 남깁니다.
- 수동 검증 요약·번역은 editorial/YYYY-MM-DD.json의 items에 id,title,text,kind,sourceUrl로 추가할 수 있습니다.
- Actions의 Deploy ETF News Desk에서 stored-release를 실행하면 RSS 재요청 없이 저장 기사만 공개합니다.

## 편집·확인 기준

- 국내 요약은 원문 확인 후 주체·수치·변화를 앞에 놓고 60~140자 개조식으로 정리합니다. `~함` 종결과 기자명·도입부의 단순 발췌를 피합니다.
- 본문 미확인 항목은 제목 기반 정리로 유지하며, 해외 제목 번역을 본문 요약으로 표시하지 않습니다. 수치·통화·티커를 보존하고 잘린 원제목은 일부 생략임을 표시합니다.
- 핵심 브리핑은 **기사 건수·카테고리 집계가 아니라 내용의 변화**를 정리합니다. 실제 수급의 방향과 집중 영역, 상품·제도 변화, 다음 확인 지점을 2~3문장과 3~4개 이슈로 연결합니다. 수치는 주장을 뒷받침할 때만 사용합니다.
- 같은 이슈를 반복 나열하지 않으며 확인한 요약을 우선합니다. 수동 검토본은 `briefing.reviewed=true`로 표시해 클라우드 공개 작업에서 같은 날 중복 편집을 피합니다. 검토 전 자동본도 건수 안내 대신 실제 기사 내용을 사용하며 제목만 확인한 범위를 구분합니다. 기사 원본과 관련 기사 링크는 유지합니다.
- 07:40 미갱신 노란 안내는 기존 화면의 실제 구간 판정을 사용합니다. 일부 공급자 오류가 있어도 오늘 공개본이 있으면 공개 지연으로 표시하지 않습니다.
- Sites의 과거 수집·공개 예약은 중지 상태를 유지합니다. 현재 운영에는 Site 인증키·사용자 PC·PowerShell이 필요하지 않습니다.
